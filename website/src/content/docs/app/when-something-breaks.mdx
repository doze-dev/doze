Read what went wrong in the app and fix it: a crash, a port someone else holds,
or a `doze.hcl` that no longer loads.

The examples break Larder, the made-up grocery service the docs use, on
purpose.

## Where you hear about it

The stack's tab gets a red count, and so does the bell at the top right
(<kbd>⌘⇧N</kbd>). The bell's panel, **Needs you**, lists what is broken and each
item's fix. When the window is closed or on another page, the app sends a
notification for a crash, a failed task, or a service that never became ready;
see [Menu bar and notifications](/app/menu-bar/).

## A crash

A service that exits soon after it starts is **crashing**. doze waits and tries
again, five times by default, waiting a little longer each time. After the last
try it is **failed** and waits for you.

<HowTo>
<Fragment slot="app">

<Steps>

1. **Read What it said.** Copy takes the lines with you.
2. **Fix the cause** in your code or in `doze.hcl`.
3. **Press Try now** (<kbd>r</kbd>). Or **Stop trying** (<kbd>s</kbd>) while you
   look, and flip its switch on when you are ready.

</Steps>

</Fragment>
<Fragment slot="terminal">

```sh
doze logs orders        # what it printed, also while it is down
doze restart orders     # try now
doze off orders         # stop trying; nothing wakes it
doze on orders          # back into the run
```

</Fragment>
</HowTo>

How many tries, and how long between them, is the `restart` block of an `app`
or a `service`:

```hcl
app "orders" {
  run = "go run ./services/orders"

  restart {
    max_retries = 10
    backoff     = "2s"
  }
}
```

## A port that is taken

When an app cannot listen because another process holds its port, the page
names that process and its pid, and offers two ways out.

doze never stops a process it did not start without asking, which is why this
is a question. From a terminal, `lsof -i :8000` names the same process.

## A doze.hcl that does not load

Save a broken `doze.hcl` while the stack runs, and the stack keeps running as
it was. Its page says what is wrong, on which line, in the same words as
`doze lint`.

Fix it in your editor. The page checks the file again each time you save. Once
it loads, **Restart the stack** applies it: a running stack keeps the file it
started with. A `doze.hcl` that changed and still loads offers the same restart.

```sh
doze lint       # the same check, from a terminal
```

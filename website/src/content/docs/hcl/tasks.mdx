Run your migrations, dependency installs and seed scripts as tasks: before
the apps that need them, and again only when their files change.

A `task` is a command that runs to completion. An [app](/hcl/apps/) or a
[service](/hcl/your-own-services/) keeps running; a task finishes, and doze
remembers how it went.

## A migration

Larder, the made-up shop the docs use as an example, migrates each service's
schema with a task:

```hcl
task "migrate-catalog" {
  run    = "go run ./platform/cmd/migrate services/catalog/migrations"
  inputs = ["services/catalog/migrations/*.sql"]
  env    = { DATABASE_URL = "postgres://catalog:catalog@${module.postgres.address}/postgres?sslmode=disable" }
}

app "catalog" {
  run   = "go run ./services/catalog"
  port  = 8002
  after = [task.migrate-catalog]
}
```

- `after = [task.migrate-catalog]` makes the task run before `catalog`
  starts. If the task fails, `catalog` does not start.
- The task references `module.postgres`, so Postgres is woken first.
- `inputs` are globs, relative to the task's `dir`. The task runs again when
  the content of a matching file changes; otherwise it is skipped as up to
  date.

## When a task runs

Each time something that lists it in `after` starts, and on `doze up`, doze
asks whether the task needs to run. It runs when:

- it has never run;
- it failed last time;
- it has `inputs` and their content changed since its last run.

A task with no `inputs` runs once, and after it succeeds, not again until you
run it yourself. The task's record, with its exit code and
the fingerprint of its inputs, is kept in `.doze/state.json` beside
doze.hcl.

An app that `watch`es its files also watches the `inputs` of the tasks it
waits for: edit a migration, and the migration runs, then the app restarts.

## Installs, keyed on the lockfile

```hcl
task "install-storefront" {
  dir    = "apps/storefront"
  run    = "bun install --frozen-lockfile"
  inputs = ["package.json", "bun.lock"]
}

app "storefront" {
  dir   = "apps/storefront"
  run   = "bun run dev"
  port  = 5173
  after = [task.install-storefront]
}
```

The install runs on a fresh clone and again whenever the lockfile changes,
never on a plain restart.

## A task you run by hand

```hcl
task "seed-catalog" {
  run    = "go run ./platform/cmd/migrate services/catalog/seed"
  manual = true
  after  = [task.migrate-catalog]
}
```

`manual = true` keeps it out of every start: it runs only when you ask. Its
own `after` still holds, so seeding migrates first.

## Migrations belong in tasks, not `setup`

An app's `setup` runs once per data folder, which is the wrong trigger for a
migration: it would not run when you add a migration file. A task runs on the
change itself, before the app, and shows its runs in the app.

## A task that is never run

doze warns about a task that is not `manual` and that nothing lists in
`after`:

```text
task "seed" runs only by doze task seed: nothing lists it in after; add manual = true to say so, or task.seed to the after of what needs it
```

A task takes `run`, `dir`, `env`, `env_file`, `inputs`, `manual`, `after`,
`enabled`, `count` and `for_each`. It has no port, no readiness and no
restarts: it runs to the end, once.

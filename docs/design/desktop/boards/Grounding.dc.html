What's real, what's new, and what each new thing needs

Checked against doze at a38cc70: the control protocol (internal/control), the journal, the dash, the detect package and the fixtures the boards use.

decidedThe app is for people; the CLI is for machines

DecisionWhy
A desktop app, Wails v3, macOS and Linux togetherBoth from the first release, every board compared on both. Go, so it imports doze's packages; a web view, so doze-aws's and doze-kafka's consoles open in it as they are. No Windows while doze doesn't run there
A menu bar (tray) app plus a windowThe tray is ambient and about as light as the daemon (18 MB); the window is released when closed. Stock GNOME hides tray icons, so on Linux the window and notifications must stand alone
Built around the map, inside a service, and the timelineWhat a terminal can't do, on top of the TUI's daily loop
The TUI is retiredFrozen now; once the app matches it on macOS and Linux, a bare doze opens the app (or prints status with no display); then the dash is removed. status -w and logs -f stay
The CLI stays first-class, for machinesCI, coding agents, scripts and remote machines have no screen: --json everywhere, real exit codes, every action the app has, nothing that needs a display or a person, a guide for agents. No polish as a human interface
One binary: CLI, app and daemonInside Doze.app on macOS, linked into the PATH; the same file on its own on servers and in CI. Linked but unused, Wails adds 14 MB, 3 ms a command and 2.4 MB footprint
No cgo (Wails' purego mode)doze keeps releasing as pure Go from one Linux runner
One instance; each stack a tabOpening doze again, or doze open elsewhere, brings the one window forward at that stack's tab. ⌘W closes a tab and leaves the stack running; quitting the app leaves stacks running
Drag to install, set up on first launchAs OrbStack does: four steps in the app, one admin prompt for the PATH link and .doze names, each skippable and repeatable from Settings. Not a .pkg: the same screens repair the setup and work on Linux
Consoles get a whole tab, unchanged; or the browserdoze-aws and doze-kafka open as their own tab beside the stack and fill the window, exactly as in a browser. Links into them are their own URLs; the only module work is taking the theme from the address. A setting sends them to the browser instead
Light by rule, checked in CIOne web view; no frontend framework (Go templates, htmx, Alpine, as the consoles); live data only for what's on screen; the window destroyed on close; no blur, looping animation or WebGL; budgets for menu bar, open window, after close, CPU at rest
Start what you choose; rememberedUp starts the services you tick and what they need, like doze up api web. Down remembers which were up, and the next Up offers the same set; Up everything is one click away. Tabs and pages come back too. Anything left asleep still wakes when something connects
PositioningOrbStack runs your containers. doze runs your stack, and understands it.
First, checkWhether the no-cgo binary runs on headless Linux without GTK and WebKitGTK; the spike on Linux (tray on KDE and GNOME, memory); and the daemon's idle RSS with the GUI linked against the 34 MB bench budget

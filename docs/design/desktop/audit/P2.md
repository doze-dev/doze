# P2 audit: parity

Independent audit of commits 3d7927e..af1e7a6 (2026-11-05). Reference: the frozen TUI in
`internal/dash` (modal.go, keymap.go, messages.go, console.go, blocks.go) and the boards in
`docs/design/desktop/boards/`, rendered at 1280×800 and put beside the screenshots the browser
tests take (`test/desk-e2e/.desk-look/*-chromium.png`). All four gates are green (results at the
end); the findings below are what the gates do not see.

Verdict: the parity table's eleven rows are not all green. Rows 4, 7, 8, 10 and the D8
notifications each have at least one should-fix below; nothing found is a wrong word or a wrong
button order in a dialog, which is where the risk was. Nothing blocking in the strict sense (the
dialogs say the dash's sentences in the dash's order), but eleven should-fixes, three of them
behaviour the UI advertises and does not do.

## Findings, most severe first

### Should fix

1. **Reset: Enter after typing the name cancels; the dash resets.**
   `internal/dash/modal.go:347-351` — typing moves `btn` to 0, so ⏎ once the name is typed runs
   the reset. `internal/desk/frontend/src/components/dialog.tsx:11,36-42` keeps `at` at
   `d.default` (Cancel) whatever is typed. `test/desk-e2e/tests/parity.spec.ts:82-84` locks the
   opposite in ("Enter on the default is Cancel, even once the name is typed"). Scenario: type
   `db`, press ⏎ — the dialog closes and nothing is reset; a TUI user does this by habit. The
   board does not draw this moment either way, so it is a reference deviation, not a board one.

2. **⌘K with nothing typed lists every instance; the dash lists the selected one and the stack.**
   `internal/dash/modal.go:176-186` hides rank-2 rows until something is typed and, under three
   characters, keeps one row per verb among other instances. `internal/desk/view/palette.go:93-131`
   has neither rule. Visible on the Search board: "sl" draws three rows (sleep db, sleep web,
   sleep everything…); the built page draws six (db, everything, api, web, cache, mongo) and with
   nothing typed about forty, with no scrolling of the selection into view (palette.tsx has no
   `scrollIntoView`). Row 4 is marked green against this board.

3. **A console tab goes dead after its daemon restarts.** `internal/desk/hub/console.go:59-87`
   binds a watch to the `*stack`; `hub.go:186-191` cancels and deletes the stack when its socket
   goes. `Hub.Watch` (`hub.go:255-266`) also records `wants` at hub level so stats and logs are
   re-subscribed when the stack reappears; `WatchConsole` keeps nothing at hub level, and
   `SetFocus` (`serve/service.go:362-368`) only watches when the stack is known at that moment.
   Scenario: postgres activity tab open, `doze down; doze up` — the tab shows "reading the
   console…" or stale rows until the person navigates away and back. Same when the app opens
   straight onto an instance page before the hub has seen the socket.

4. **A crash loop notifies once per retry, not once per episode.** `internal/desk/notify/rules.go:57-65`
   ends the episode whenever the state is not Troubled; the registry moves crashing → booting on
   each retry (`internal/registry/registry.go:118-123,181-186`), so a 5-try loop whose retries run
   a few seconds yields up to five notifications (same ID, so macOS replaces the banner, but each
   delivery alerts). `rules_test.go:39-43` tests exactly this transition as "a new episode".

5. **"Nothing about what was already so when the app first looked" holds only for the first push.**
   `rules.go:66,94` — `primed` is one bool for all stacks. A stack the hub finds after the first
   push (its socket appears 300 ms later, or `doze open ~/other` an hour later) has its hour-old
   crash announced as news. Should be first-sight per stack.

6. **A notification's Show loses its instance on a cold open, then leaks into a later open.**
   `internal/desk/serve/service.go:509-531` `Pending()` resolves `pendingDir` without consuming
   `pendingInstance` (set at :697). Scenario: window closed, click "api crashed" → window opens on
   shop's *home*, not api; later `doze open ~/other` → `push()` (:211-213) navigates to
   ~/other's "api" page: "other has nothing called api".

7. **Crash overview: "Its last run" is the last eight lines of every run.** `service.go:316-320`
   takes `Lines[n-8:]` regardless of `Run`. The built screenshot shows three lines of run 2
   ("slow query…", "GET /orders…", "GET /healthz…") above "started go run ./cmd/api"; the Crash
   board shows the run only. Row 7 is marked green against this board.

8. **A stream's newest rows are below the fold.** `components/console.tsx:268-298` draws all
   kept rows top-down inside `.con` (`shell.css:1061-1068`, `overflow: auto`) and nothing scrolls
   to the tail; the dash draws the tail (`blocks.go:448-450`). After ~20 rows of a kafka tail at
   28 px each, what is arriving is off screen. The fixture has two rows, so no test sees it.

9. **The console page says "db is asleep" whenever it has no state.** `console.tsx:98-101`
   substitutes "asleep" for `con.state || …` and shows the line whenever `!con.awake`;
   `view/console.go:113-121` returns `State ""` while the hub has no console yet (first paint,
   after finding 3). A fact derived in the frontend (D16), and wrong while loading.

10. **Esc on Recent messages does nothing, and the test cannot tell.** `pages/recent.tsx:19-21,43`
    draws "Back esc" and the keys bar; no component mounted on that page binds Escape (app.tsx
    has none; instance.tsx's handler is not mounted). `parity.spec.ts:135-136` presses Escape and
    asserts `h1` is "shop" — which is the Recent page's own `h1` (recent.tsx:17). Vacuous.

11. **D8's third notification is not built and not tagged.** README D8 and the Notices board's
    panel ("only these three") include "api did not become ready within 1m30s"; `rules.go`
    covers crashing/failed/error and failed tasks only. parity.md's "Beyond the TUI" lists two
    of the three without saying the third is missing.

22. `store.ts:177-186` `ask()`: a dialog answered after navigation lands on the new page.

## Code review notes without a finding

`hub/console.go` watch/release/resub is race-free as far as I can see: `gen` guards late frames,
cancel under `mu` is non-blocking, `stopConsoles` runs on drop, `Blur` releases (service test
covers it). `followConsole` deletes only the new panel's rows, so a previous panel's rows linger
in `Streams` until release (harmless, cloned on every `view()`). `consoleViews()` is cloned on
every `Stacks()` call and the service calls `Stacks()` five or six times per push; with a busy
stream that is 300 rows × panels × 6 per 250 ms — a D14 cost worth measuring, not a bug.
`InvokeSync` from the notification callback is safe (`mainthread.go:23-35` runs inline on the
main thread). Overlays own the keyboard (capture-phase `stopPropagation` in dialog, palette,
help), so page letters do not leak; `?` is guarded against inputs; ⌘K still closes the palette.

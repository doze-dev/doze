## 1. Findings

**F1. doze HEAD does not build against doze-names HEAD; the B1 and C8 fixes are
uncommitted.** `doze-names/ca.go:381-432` (`Bundle`, `BundlePath`,
`systemRootsPEM`) and `routes.go:168-191` (`AnyDeclared`, `RemoveCA`,
`Claimants`) are `git diff` only; doze calls them at
`internal/daemon/ingress.go:59`, `cmd/doze/env.go:103`, `cmd/doze/trust.go:80,88,180`.
Verified: `git stash` in doze-names, `go build ./...` in doze →
`ingress.go:59:25: ca.Bundle undefined`; restored. `go.mod:12` requires
`doze-names v0.2.0` behind a local `replace` (`:71`); no tag. A clone at the
stated commits, or a release build, has no B1 fix and no build. **Blocking.**

**F2. A stack that brings its own `cert`/`key` never gets a :443 listener.**
`internal/daemon/ingress.go:45-73` leaves `ca` nil unless `usesDozeCA()`;
`doze-names/ingress.go:226-237` starts the TLS server only `if ca != nil`, and
`:221` keys the redirect on the same test. `GetCertificate(nil)` honours
`e.Cert` (`ca.go:279-286`; the test calls it directly) but nothing serves the
port. Scenario: the documented "Bringing your own certificate" stack: the log
says `front door: https://dev.acme.com → the app` (`:70`), `https://` is
refused, `http://` is served unredirected, doctor says "nothing holds :443 yet"
(`doctor.go:351`). Start TLS whenever a domain is declared. **Blocking.**

**F3. `bundle.pem` is every certificate in two keychains, not the trusted
roots, and it folds its previous self in.** `ca.go:415-424` exports
`SystemRootCertificates.keychain` (158 here; Apple's curated `/etc/ssl/cert.pem`
has 128 — the rest are roots trustd distrusts for TLS) and all of
`/Library/Keychains/System.keychain` regardless of trust settings: on this Mac
`com.apple.systemdefault` and `com.apple.kerberos.kdc` (self-signed "System
Identity" certs whose keys any root process can use) and an Apple WWDR
intermediate; on a managed Mac whatever MDM put there, and a root set to "Never
Trust". OpenSSL takes each as an anchor. Then `internal/daemon/ingress.go:55-59`
reads the daemon's own `SSL_CERT_FILE` as `extra`, and the daemon inherits the
shell (`daemonctl.go:73`). Scenario: `eval "$(doze env)"`, then `doze up` in
that shell → `extra` is last start's bundle; it doubles each start and after
`--rotate` the old root is carried forward for ever, so rotation never reaches
in-stack clients. Use `/etc/ssl/cert.pem` plus admin-keychain CAs that pass
`security verify-cert`; skip `extra` when it is the bundle. **Should fix.**

**F4. `doze env` reproduces B1 whenever the bundle is missing.**
`cmd/doze/env.go:103-106` falls back to `root.crt` for `SSL_CERT_FILE` and
`REQUESTS_CA_BUNDLE`; only a daemon writes the bundle. Verified: after
`doze trust --print`, `doze env` printed
`export SSL_CERT_FILE='/tmp/aud/home/ca/root.crt'`. Scenario: `doze trust`,
`eval "$(doze env)"`, `pip install` → `CERTIFICATE_VERIFY_FAILED` until the
first `doze up`. Write the bundle from `env`, or omit the two. **Should fix.**

**F5. The privileged script does more than its prompt says.** `trust.go:39-60`
`routeSet()` adds every recorded route another project still declares;
`trust_darwin.go:43-47` writes each that is not routed. Verified with two
projects under one home: project 2's `--print` was headed `# route
api.aud.example to doze` and also wrote `/etc/resolver/dev.aud.example`
(project 1 only ever ran `doze up`); its `--remove --print` was headed
`# remove the domain routes…` and *installed* that file (`trust.go:160-161`).
The sudo line and the docs ("routes each domain" of this stack) under-describe
what runs as root. On macOS write only the request's domains. **Should fix.**

**F6. The doze variables override an app's own.** `runtime.go:1196-1208`
appends `extraEnv` last and `exec` keeps the last duplicate. Scenario:
`env { REQUESTS_CA_BUNDLE = "/corp/bundle.pem" }` on an app behind a corporate
proxy is silently replaced. Prepend instead. **Should fix.**

**F7. Linux `dns-setup --uninstall` aborts before untrusting the CA.**
`setup_linux.go:273` `set -e`; `:275` deletes `doze0`; `:288` appends
`cleanupScript`, whose first line (`trust_linux.go:55`) is `resolvectl domain
doze0 ~doze` with no `|| true` → exit 1 → the script stops before `rm -f
…/doze-local-ca.crt; update-ca-certificates`; the error path skips
`cleanupAfter`, so a retry fails the same way. Even without `set -e`, `:287`
removes the drop-in and the cleanup lines re-create it for a unit that no longer
exists. Nothing on Linux is tested. **Should fix (S3 incomplete).**

**F8. The remedy for a bad authority is blocked by it.** `cmd/doze/trust.go:49-53`
runs `LoadOrCreateCA` before the `rotate` branch; `ca.go:113-118` errors on an
unparsable or soon-expiring root with "doze trust --rotate makes a new one".
Scenario: corrupt `root.key` → every surface says run `--rotate` → `--rotate`
prints the same error. The same call serves `--check`, `--print`, `--remove`,
and `up.go:318-321`, `doctor.go:336-339`, so `doze up`, `doctor` and
`trust --check` create a key pair (verified: `--print` left `root.key`). C4's
"reporting surfaces use `OpenCA`" holds for `env.go` and the desk only.
**Should fix.**

**F9. Rotation while a daemon holds :443 serves leafs from the old root.**
`Rotate` (`ca.go:197-207`) runs in the `doze trust` process; the holder keeps
the loaded `c.cert`/`c.key` (`:297-316`, `:342`) and its in-memory leafs, while
the same prompt untrusts the old root. Scenario: `--rotate` → every browser
rejects `dev.acme.com` until the stack restarts; nothing says so; `bundle.pem`
is stale until then too. **Should fix.**

**F10. `--remove` with no authority on disk makes one.** `trust.go:49-53`
(`usesDozeCA(cfg) || remove`). Scenario: the CA already went with the last
`--remove` → a sudo prompt to delete a never-trusted root; `--remove --print`
leaves a fresh `root.key` behind. Use `OpenCA`. **Should fix.**

**F11. A domain added live to a stack that started with none never gets https.**
`setupIngress` runs once (`daemon.go:290`) and picks `ServeIngress`;
`dynamic.go:307-337,359-364` claim the twin and publish the :80 route only.
Scenario: `doze sync` after adding `domains` → the name resolves and `http://`
works, :443 is never bound, no CA env reaches new processes, the routes record
is not updated, and `doze url` prints `https://`. **Should fix.**

**F12. `Bundle()` has C7's race.** `ca.go:365-371` uses one fixed `.tmp` name,
no lock; every daemon with a minted domain writes it at start (`:404`). Two
daemons starting together (the app's remembered Up set) can rename a truncated
file into place → every https call from the stack fails. **Should fix.**

**F13. Untrust is presence-based and its admin-domain removal is unverified.**
`trust_darwin.go:82-84` uses `delete-certificate -t`, whose usage here reads
"Also delete *user* trust settings"; the root was trusted with `-d` (admin).
Failure is hidden by `2>/dev/null || true`, and `forgetUntrustedPrevious`
(`ca.go:214-223`) then drops the fingerprint because `fingerprintTrusted` and
`caTrusted` (`trust_darwin.go:55-70`) test keychain presence, not trust
(`security verify-cert -c root.crt -p ssl` would). Check `security
dump-trust-settings -d` after a rotate; keep `previous/<fp>.crt` so
`remove-trusted-cert -d` (mkcert's way) is available. **Minor until verified.**

**F14. Relayed answers keep the upstream TTL.** `resolver.go:196` writes the
upstream reply verbatim; only doze's own answers carry TTL 10 (`:266`).
Scenario: the real `dev.acme.com` (TTL 3600) resolved while the stack was down;
`doze up`; mDNSResponder serves the real address for up to an hour. **Minor.**

**F15. Small ones.** The redirect reflects the raw `Host` (`ingress.go:314-316`)
and `lookupDomain` (`domains.go:89-98`) validates nothing left of a wildcard;
loopback only, so no open redirect — use the normalized owner. `DOZE_ZONE=off`
turns every command into "add `domains = true` to the defaults block"
(`decode.go:63`, `domains.go:164-166`; verified, exit 5). `trust.go:73-77`
slices `fp[:12]` and `fingerprintTrusted("")` is true (`Contains(out, "")`), so
a `previous.json` entry under 12 chars panics `doze up`, `doctor`, `trust
--check` and the desk. `declared()` (`routes.go:149-156`) is `Stat`: an

promises a doctor line for a domain that does not resolve despite the route,
and `domainChecks` (`doctor.go:309-357`) has none; depth-2 names and containers
are in the resolution and plan, not the docs; Windows `doze up` says "needs a

`/etc/resolver/<domain>` that "points elsewhere" (`trust_darwin.go:33`) is

Checked and fine: `shellQuote` on every path and fingerprint in every script;

## Resolution (2026-11-05, after the audit)

Fixed in doze-names eefde9b.. and the doze commit after 6e8a9ee. The
design change behind most of it: the https door is no longer a choice the
daemon makes at start. It is bound with the plain door whenever names are
on, and the holder opens the authority from disk per handshake
(`CurrentCA`, reloaded when the root file changes).

- **F1** — committed (doze-names 1c9271b); doze builds against doze-names HEAD.
- **F2** — `ServeIngress` serves :443 too; a domain with `cert`/`key` is served with no authority on the machine (test: own files through the door, no `root.crt` made).
- **F3** — the bundle is `/etc/ssl/cert.pem` plus the System keychain's CAs that pass `security verify-cert -L -l -p basic` (verified on this Mac: a public root passes, the three System Identity/WWDR certificates and an untrusted root fail); doze roots are stripped from an inherited `SSL_CERT_FILE`, and one that is the bundle itself is skipped (test).
- **F4** — `doze env` writes the bundle (`EnsureBundle`) and never falls back to the root for the two store-replacing variables; without an authority it prints no CA variables (CLI test).
- **F5** — `routesScript(keep, write, drop)`: macOS writes the request's domains only; Linux restates the set and the prompt says so; `--remove` installs nothing (test with two projects under one home, `--print`).
- **F6** — doze's variables replace an inherited copy and yield to one the process was given on purpose (test).
- **F7** — `resolvectl … || true`; uninstall on Linux no longer restates routes; the CA's trust is removed by name even when the files are unreadable (`untrustUnknownScript`). Still untested on Linux.
- **F8/F10** — `--check`, `--remove`, `up`, `doctor` use `ProbeCA` (nil, or an error they report with the `--rotate` remedy); `--rotate` uses `RotateCA`, which works on a broken root and remembers it; only the plain `trust` and `--print` create one (CLI test: `--check` and `--remove --print` leave no `root.key`; a broken key sends `--check` to `--rotate` and refuses `--print`).
- **F9** — the holder reloads the root (test: a rotation from another handle is served within one request; the old root no longer verifies); `--rotate` rewrites the bundle and tells the person to restart running processes.
- **F11** — `refreshIngressRoutes` calls `ensureDomains(live)`: record, authority, env for processes started from then on, with a log line; :443 is already bound (daemon test: a domain added to a stack that started with none).
- **F12** — `Bundle` runs under the authority's lock; `writeFileAtomic` uses a per-process temporary name (test: eight concurrent writes).
- **F13** — admin trust is removed with `remove-trusted-cert -d <file>`; a rotated-out root is kept under `ca/previous/<fp>.crt`; `caTrusted`/`fingerprintTrusted` use `verify-cert`, not presence. The removal itself is still unverified with sudo (open).
- **F14** — relayed answers' TTLs are capped at 10 s, through compressed names (unit test and the forwarding test).
- **F15** — `previous.json` entries validated (64 hex) and `shortFP` guards the slice; the redirect uses the normalized host, needs a doze process on :443, and reads the registry once; `IsDomain` no longer on the request path; `DOZE_ZONE=off` message says so; "need/needs"; wildcard-only `https://` line; `doze doctor` resolves each routed domain through the system resolver and compares it with the stack's address; docs cover depth-2 wildcards and containers; Windows `up` says the platform is not supported instead of pointing at `doze trust`; a foreign `/etc/resolver/<domain>` is reported and never written or removed; project folders are keyed with symlinks resolved. An unmounted volume still reads as a deleted project (open).

Addendum, same day: the resolver with doze fully down is closed on macOS.
The network daemon (doze-names `netd.go`, version 2 of the launchd job)
joins the resolver's first-come loop after it drops root, so with no doze
program running it answers the zone from the registry and forwards a
routed domain nobody declares to the machine's upstreams; a program that
starts later stands by behind it, as behind any peer. `Check` reports a
job from an older setup until setup is run again. Unit test against a
fake upstream, an e2e against the installed daemon (`DOZE_NAMES_E2E`),
and a test of the outdated-job check. Linux has no daemon, so the trap
stands there and the docs say so; the sudo by-eye of the reinstalled
daemon is the owner's.
